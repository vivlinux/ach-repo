AHC Visual Intelligence Hackathon

Fix the labels first, then the cascade is small enough for a laptop

Eleven anomaly classes across CCTV, dashcam and drone footage — no CUDA, nothing hosted in the runtime path. Two bands: an offline pass that corrects the training labels, and a runtime path where a frozen encoder scans every frame and a 1M-parameter head reads each 8-second window in order. A vision-language stage sits behind the same interface — we measured it, and the shipped run does not need it.

Evidence, including what failed

Every change to the model failed. Fixing the data worked.

A larger vision-language model, a verification gate, and a rewritten prompt were each tested against a control. All three came back flat or negative. What moved the score was discovering that the training labels were wrong — and correcting them.

The finding: folder labels disagreed with the footage

Each training folder is named for a class, but the clips inside often showed something else. road_spill_or_debris was 99% collision footage — debris is what a crash leaves behind. Re-deriving every label from its own description_summary changed 520 of 2,952 rows.

That moved 386 collisions into traffic_accident, the single most common event in the test set — and emptied road_spill_or_debris entirely, revealing it had no genuine examples at all.

What the corrected data bought

0 → 3accidents detected (of 13)
24 → 4blocking-traffic false alarms
17 → 0wrong-way false alarms

Zero-shot never found a single collision: it compares a clip to the text embedding of a class name, and the phrase “vehicle driving the wrong way against oncoming traffic” sits close to any two-way traffic scene. The head reads the 16-frame sequence instead, and with only 35 surviving wrong-way examples it learned the class was unreliable and stopped predicting it — removing every false alarm the benchmark had flagged.

The three that failed

No gain

A 2.7× larger model tied

Qwen3-VL-8B matched Qwen2.5-VL-3B at 14.1 — better at naming the class (.458 vs .417), worse at anomaly-vs-normal (.667 vs .708). Exactly cancelling. Capability was never the bottleneck.

Cost us points

The gate was calibrated and still lost

It removed 14 false alarms and 0 real events, but caught only 30% of them, and on one video removed the sole interval and forfeited the alert credit. Net 29.6 → 27.6. A gate can drop a guess; it cannot correct one.

Backwards twice

Our prompt reasoning was wrong

We expected a less cautious prompt to recover missed anomalies. It produced more “normal” answers on both models (14.1 → 13.5). Frame count was isolated separately and was not the cause.

What we would do next

  • Object detection and tracking. wrong_way_driving and vehicle_blocking_traffic ask whether one vehicle's heading opposes the surrounding flow. Whole-frame appearance cannot express that — which is why the honest outcome was to stop predicting them rather than to predict them badly.
  • More cameras per class. The head overfit hard (train 0.011 / val 0.296) and we kept the best-validation epoch. Three classes come from essentially one camera each, so it memorises cameras rather than concepts.
  • Recover the classes with no data. road_spill_or_debris ended with zero genuine examples and loitering never had usable annotations — both are currently undetectable by construction, not by failure.
